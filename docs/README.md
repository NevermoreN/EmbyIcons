## 已确定的需求

| 编号 | 要求 | 对应计划 |
| --- | --- | --- |
| R1 | 以 Rust 为业务主体，迁移当前实际启用的规则、缓存、预绘调度、绘图、评分和必要管理业务；范围见 05，不要求移植上游全部功能 | P1、P3—P7 |
| R2 | 保留 Emby 必需的薄 .NET 接口适配层；设置页面继续使用现有 HTML/JavaScript | P1、P2、P7 |
| R3 | 原图只读，不覆盖、不替换、不删除；增强结果只写 Emby 指定的缓存路径，沿用宿主成品/缩放缓存 | P0、P4、P6 |
| R4 | 修复非画面变化引起的缓存标识漂移，核对列表、预绘、实际请求和磁盘成品的一致性 | P0、P3、P8 |
| R5 | 入库后在后台主动制图；不能以用户第一次访问图片作为正常绘图触发器 | P0、P4、P5、P8 |
| R6 | 兼容已有配置、独立插件身份、稳定标识、磁盘状态及可复用的图片，不因换语言全量清缓存 | P2、P3、P8、P9 |
| R7 | 维持 05 中保留功能的语义和效果；未使用功能从本次实现与验收中移除，旧配置字段仍需兼容保留 | P6—P9 |
| R8 | 元数据刷新后自动在后台核验；画面相关输入变化则重新制图，只有时间戳变化则复用有效成品 | P3—P5、P8 |
| R9 | Emby 计划任务中可手动启动制图并保存到宿主磁盘缓存，提供真实完成进度和失败结果 | P4、P5、P8 |
| R10 | 只制作 Primary 海报；PNG 无损保存绘图结果，不能以降低分辨率、颜色量化或有损编码换速度 | P2、P5、P6、P8 |

“入库后制图”指收到事件后立即进入后台调度，在元数据和原图可用后执行；不要求在入库事件回调内同步完成绘图，也不声称“文件尚未下载就已经制图”。

2026-11-05 只读核查确认：2 个 Profile、16 个映射库（7 个电影库、9 个剧集库），两者只启用海报和 6 类评分/分级/收藏叠加。语言、技术参数、音乐、文件名/标签规则等不再列入本轮重构交付。新功能请求 R5/R8/R9 和缓存修复 R4 保留，不能因为当前尚未实现而裁掉。

目标交付平台先覆盖当前 NAS 使用的 Linux x86_64 Emby 容器。Windows、macOS、ARM64 不在本轮已确认的部署范围内；代码和 ABI 不应写死阻碍后续移植的假设。

已纳入的性能方向：查询时限定适用海报、统一去重与画面输入比较、评分网络等待不占绘图槽、精简跨语言传输。宿主 `GetEnhancedImage` 入口与 PNG 无损压缩参数属于候选优化，只在既有最小验证中确认行为或发现实际瓶颈后采用，不追加独立测试计划。详见 02 的 4.3、6.5 和 9.1。

## 重构前基线结论

1. 当前为 C# / `.NET Standard 2.0` 插件，使用 SkiaSharp 绘图，HTML/AMD JavaScript 提供设置页。
2. Emby 原本就把增强图片和缩放图片放在磁盘。插件额外维护稳定标识和输入状态，目的是让已有成品继续命中。
3. 当前 `ItemAdded/ItemUpdated` 主要驱动缓存失效和后台输入核验，没有直接接入自动制图队列。
4. 当前 `PreDrawPostersTask` 已通过 `IImageProcessor.ProcessImage` 预绘。此次读取 NAS 的实际任务确认 `Triggers=[]`，任务空闲，存在一次完成记录；这不证明当前已有入库自动制图。
5. 当前图片请求在 Emby 缓存未命中时仍可进入 `EnhanceImageAsync` 制图，因此尚不满足严格的“访问不触发绘图”。
6. 先前观察到列表图片标识与实际增强文件后缀不能逐项对应，首次抽查 6 个样本中 4 个产生新缓存；原因尚未闭环，不应直接定性为缓存漂移或必要更新。
7. 全面迁移可按阶段完成；最终业务应在 Rust 中，阶段性保留旧 C# 实现仅用于对照和受控回退。

## 执行纪律

- 第一阶段只收集足以解释问题的证据；不要先修改缓存格式或更换绘图库。
- 现有代码、Rust 对照实现不能同时写同一个状态目录。
- 不把插件版本、部署时间、进程启动时间加入普通图片的失效条件。
- 不清空 `cache/images`；不为了“命中”把原图或旧成品写到新成品标识下。
- 后续实施按工作包更新实际完成状态和证据；未经验证的项目保持未完成。
- 测试按最小必要范围执行：复用现有用例和阶段证据，只补真实缺口，不做跨层重复测试、组合穷举或无疑点的反复验证；详见 04。
- 生产切换遵循 P8/P9 门禁；当前实际版本、后台补齐进度及限制以 07 为准。
