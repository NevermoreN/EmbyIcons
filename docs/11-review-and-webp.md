# 全局收藏复查与 WebP 修复

版本：`5.61.1.7-nevermore.rust.4`。

## 发现与修复

1. **真实 WebP 海报制图失败。** 生产有一项持续报 `image decode failed`，输入为 32,894 字节的 WebP，尺寸 480×640。当前 Skia 发布包没有 WebP 解码器。宿主吞掉增强异常并返回原图，提交时又被原图保护拒绝，产生了容易误解的“不能覆盖原图”错误；实际没有写坏原图。新增固定版本的纯 Rust `image-webp` 解码，将 RGB/RGBA 像素交给现有渲染器，输出仍是原尺寸无损 PNG。不引入或改动 Emby 自带动态库。
2. **旧的无收藏结果可能删除新收藏任务。** 原先观察结果在“不适用/没有数据”分支直接删除记录，之后才检查事件版本。现在先检查观察任务的所有权和事件版本，过期结果不能清除新收藏或新观察任务。
3. **快速取消再收藏会重复使用作业版本。** 记录删除后，旧的局部计数会从头开始，旧绘图有机会被当作新作业提交。事件和作业使用进程内单调分配的版本，启动时从现有记录的最大版本继续；不改变画面指纹或缓存键，不使整个图库缓存失效。
4. **正常取消和过期作业被误计为失败。** 绘图前发现版本过期、提交时发现记录消失或所有权改变、正常退出时取消，均按放弃旧作业处理。只释放仍属于该作业的状态，保留新作业，不加失败计数/退避；真实解码、I/O、渲染错误仍保留原有有限重试。

上述变更不扩展海报范围，不恢复已移除的其他功能，不改变库映射与全局收藏的规则。状态中的观察所有权不落盘，持久化格式和 ABI 版本保持兼容。

## 最小验证

仅新增两项测试：WebP 的 RGB/RGBA 解码与透明度；过期观察、旧作业提交/失败/取消、删除重建后版本唯一及新收藏保留。加上现有三项回归，共 5 项通过；发布构建 0 警告、0 错误。

生产验收将重试上述实际失败的 WebP，核对增强图、原图摘要、插件日志和手动任务；结果完成后记录。
