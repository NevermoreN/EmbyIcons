# 03 分阶段实施与任务拆解

已实施 Rust 保留业务并通过隔离主流程和生产试点，历史库补齐仍在后台继续。已勾选项表示实现完成且引用最小主流程证据，不代表逐行另跑测试；原历史 4/6 样本的全因归属与无真实实例的合集事件不冒充验证。实际证据见 [07 实施记录](07-implementation-status.md)。以下保留原工作包及验收要求；未单独验证的细项不冒充完成。总目标与需求编号见 [入口](README.md)，技术约束见 [02](02-rust-target-design.md)，验收矩阵见 [04](04-validation-and-rollout.md)。

实施范围已按当前 Emby 配置收紧，详见 [05](05-current-usage-and-scope.md)：只迁移六类叠加、适用电影/Series/合集的 Primary、内置素材及 PNG。P0—P9 编号保留，未使用功能不再作为各阶段的产出或验收项。

所有阶段遵循 [04 的最小必要验证规则](04-validation-and-rollout.md)：验收条件不是新增测试数量要求。复用同一组样本和已有证据；每次改动仅运行直接相关的最少检查，缺覆盖才补测，通过即停。

## 1. 依赖与完成定义

```mermaid
flowchart LR
    P0[P0 宿主行为与根因] --> P1[P1 契约与原型]
    P1 --> P2[P2 .NET 适配与加载]
    P2 --> P3[P3 Rust 缓存与规则基础]
    P3 --> P4[P4 预绘与成品提交]
    P4 --> P5[P5 入库与恢复闭环]
    P3 --> P6[P6 六类叠加与 Rust 绘图]
    P4 --> P6
    P5 --> P6
    P6 --> P7[P7 管理与评分完整迁移]
    P5 --> P8[P8 全链与性能验收]
    P7 --> P8
    P8 --> P9[P9 生产切换与交付]
```

P4/P5 可以暂用 C# 参考绘图器验证调度，不能因此宣布 R1 完成。P6/P7 把对应业务真正移入 Rust 后，P8 才能进行全面迁移验收。

参考后端只能执行受控的纯绘图/评分操作，不能直接沿用会写 `ImageCacheState` 的整套旧生产增强器。此时状态仍只有一个所有者；参考结果写隔离输出或交给当前宿主作业提交，不能让 C#/Rust 同时更新真实分区。需要对照旧行为时读取副本，不改变生产键。

表内 `P2` 等阶段依赖指该阶段全部工作包完成；P6 可在规则准备上先行，但整体完成须等 P4/P5。P2 的影子接入只验证 DTO 和只读边界，Rust 键算法完成后的真实键对照放在 P3.2，避免 P2/P3 互相等待。P7.1 前评分暂由现有 C# 参考服务提供并明确登记，不把迁移中的中间态计作最终完成。

最终完成必须同时满足：业务迁移清单无缺项、严格入库预绘成立、宿主缓存标识与实际文件闭环、旧数据可迁移及回退、实际端到端性能已测。不能用 Rust 代码占比、编译通过或微基准倍数代替这些条件。

## 13. 必须保持的范围约束

- 不把业务重构缩减成单一解析器替换，也不在本轮规划之外追加媒体服务器重写、独立 Web 服务、数据库平台或前端框架迁移。
- C# 适配和浏览器资源的保留不属于业务漏迁；仍在 C# 执行缓存决策/聚合/绘图的模块则必须登记为待迁移。
- 按 05 裁剪未使用功能；保留功能变更须记录理由与兼容方案，不静默删除旧字段或忽略未支持设置。
- 计划任务和事件队列统一管理；不能以用户请求补绘掩盖入库触发缺口。
- 测试只做最小必要集合；跨阶段/跨层复用证据，不默认全量测试、压力测试、多轮基准或重复重启。通过后无新变化即停止。
- 用户已经授权开始重构；按阶段实施，不把未完成的原型直接切换到生产或启动全库预绘。
