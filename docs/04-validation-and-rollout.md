# 04 验证、性能、迁移与上线方案

本文件保留实施前制定的验收方式，不逐项代表已运行的测试。实际完成证据、生产版本和剩余限制见 [07](07-implementation-status.md)，不为逐行勾选而重复执行。阶段编号见 [03](03-execution-plan.md)。

功能范围按 [05 当前使用情况与范围裁剪](05-current-usage-and-scope.md) 收紧。已有测试可以作为现状证据，涉及被移除功能的测试不再强制移植到 Rust；宿主隔离、缓存兼容和并发提交约束仍保留。

## 0. 最小必要验证规则

测试以最少的样本和执行次数证明本次改动正确，不追求数量、覆盖率指标或完整测试平台。

- 优先运行与改动直接相关的现有用例；只有真实缺口才补测。不照搬全部 126 项，也不在 Rust 单元、.NET 集成、端到端三层重复断言同一规则。
- 一个问题放在能证明它的最低必要层：纯签名/规则用小型参数化用例；只有宿主路径、事件和文件提交问题才启动真实 Emby。
- 同一组样本兼做功能、标识、文件和耗时观察，不为每个图标、媒体、配置和错误类型排列组合。不能把大量独立验证塞进一个长流程来假装测试变少。
- P0—P7 已对当前实现验证且后续未受影响的结论，P8 直接引用；P8 仅补跨模块缺口和受后续改动影响的部分。
- 证据注明实际后端和版本。C# 参考绘图器通过不等于 Rust 已通过；切换 Rust 改变的绘图/ABI 路径需在同一组样本上验证一次，其余未变结论直接复用。
- 构建、测试、lint、类型检查、端到端检查按需选择，不机械全部运行。低影响文档修改只检查改动和链接。
- 验证通过即停止。只有新改动、失败、具体未解疑点或样本不足以支持性能结论时才增加验证；说明新增验证要解决什么问题。

以下表格是覆盖要求及证据来源，不是一行一个新测试或每阶段重跑的清单。发布门禁引用已有证据，不触发第二套测试。

## 2. 最小代表样本

| 维度 | 代表样本与复用方式 | 验收证据 |
| --- | --- | --- |
| 媒体与图片类型 | Movie、Series、符合 B Profile 的 BoxSet × Primary | 两个 Profile、映射范围、部分/完整实体一致；不误绘单集/季或未映射库 |
| 六类叠加 | 社区/烂番茄/爆米花/MAL 评分、分级、收藏数 | 数值、来源、缺值处理、优先级及缺图行为与当前一致 |
| Lite 与合集 | Series 本体数据、B 合集 Profile、A 合集不支持 | 不错误增加子项技术聚合，不把所有合集都设为可绘 |
| 图标资产 | 内置素材、缺失图标、现有命名/变体、模板复用 | 图标选择与字体正确；无自定义目录业务要求 |
| 布局 | 当前左上评分/收藏竖排、左下分级、尺寸/边距/间距、文本参数 | 两个 Profile 分别对照像素/几何、字体、色彩和透明度 |
| 编解码 | 原图 JPEG/PNG 解码、方向、平滑、原尺寸、无损 PNG 成品 | 扩展名、宽高、色彩和透明度一致；不降尺寸、不量化；调压缩时复用同图检查解码像素一致 |
| 管理与未支持设置 | 必要预览、编辑、导入导出、统计/排障、进度与取消；旧字段保留 | 权限正确、预览不污染成品；未支持启用项明确提示，界面无无效入口 |

同一底层版本下优先要求确定性输出或可解释的像素等价；跨图形库版本时先定义并核实视觉容差，不能为了让测试通过随意放宽。PNG 文件压缩字节不同不必然代表像素不同，但不能忽略布局、颜色、文字缺失或尺寸变化。

绘图初始只选 3 张已确认存在的代表海报：A 的 Movie、A 的 Series、B 的 Movie，覆盖两个 Profile、JPEG/PNG 原图和当前布局。六类叠加/缺值用同一组脱敏输入夹具表达，不为凑齐评分反复联网找媒体。B 的适用 BoxSet 尚未证实存在，先用现有或小型数据用例核验成员/Profile 适用性；只有真实实例或独立绘图分支需要验证才复用一张海报增加该输入变体。不做类型 × Profile × 图标的笛卡尔积，不逐页做 UI 自动化。

## 3. 缓存验证合并执行

| 情形 | 预期 | 必须记录 |
| --- | --- | --- |
| 旧键兼容与无关变化 | 小型参数化用例比较旧绑定、部分/完整实体、Profile 学习、时间戳及无关设置；不为每项启动宿主 | 插件键和输入指纹；沿用现有可用夹具 |
| 重启/内存淘汰后命中 | 沿用主流程的同一张成品；一次重启与一次缓存淘汰观察同时服务恢复验收 | 列表 Tag、准确宿主路径、draw、内容/mtime |
| 相关输入变更 | 在元数据刷新流程中核验新图提交及标识，不另做同义绘图测试 | 旧/新输入、作业版本、实际文件、提交顺序 |
| 评分周期与失败 | 小型数据用例核验值不变/请求失败复用；真实 API 不反复联网测试 | 旧评分、键与请求合并结果 |
| 提交/恢复问题 | 复用第 4 节的必要故障验证；分区损坏只复用相关现有用例，不新增全库恢复演练 | 未提前就绪、无半成品、影响范围正确 |

真实文件验证必须定位到本次宿主返回的确切成品。按源图前缀统计文件集合只能辅助诊断，不能替代 Tag/outputFile 一致性证明。HTTP 200 可能是原图回退，也不能单独作为增强成功证据。

零重画只适用于“画面输入未变且磁盘成品仍有效”的情况。原图变化、需要显示的新评分、损坏恢复或被宿主清除的成品可以产生必要制图，但必须是后台任务且原因明确。

## 4. 一条主流程与必要故障验证

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| 主流程：入库 → 更新 → 手动任务 → 命中 | 一项媒体原图迟到后自动绘制；相关更新重绘、无关更新不画；从同组样本中选一张缺成品的历史海报由手动任务制作，再确认成品复用 | 自动与手动都能真正制图保存；准确路径/键一致；任务不提前完成，有效成品不重画 |
| 去重与依赖 | 用同一个小型参数化用例表达重复事件/手动共享、缺输入延期、取消归属和合集 Profile；无独立宿主问题不重跑端到端 | 同图不并发绘制；任务有终点、不误报延期为保存；不扩范围，不做全库压力测试 |
| 未就绪/成品缺失 | 在隔离宿主的同一项上观察首次未就绪与移走缓存后的请求及后台恢复 | 请求 draw=0，原图不污染增强/缩放缓存，后台可补齐 |
| 提交失败与版本过期 | 选一次可控编码/提交失败，再用已有或最小生成号用例验证旧作业不能发布新版本 | 失败不就绪、无半成品；不逐一枚举同路径的磁盘/网络/权限错误 |
| 恢复与关闭 | 与第 3 节共用一次带未完成作业的重启，连带检查关停/取消及成品复用 | 可续作、不全库重画、无释放后调用；不反复重启或杀进程 |

用隔离测试库证明这些场景；不能在生产中删除真实图片制造故障。生产仅做必要的小范围正常请求与事件观察。

## 5. ABI 与资源生命周期

- 一个小型契约用例承载实际使用的 UTF-8/Unicode、GUID、空值和批量 DTO 的往返与释放；不单独为每个字段建测试。
- 真实宿主加载/关闭直接复用主流程及一次恢复观察；只增加一个不匹配 ABI 的失败检查，确认不自动退回请求时 C# 制图。不对共享错误处理逐一模拟所有加载失败。
- 同图去重、关闭取消和缓冲区释放复用对应阶段的验证。只有出现增长、崩溃或并发疑点，才增加资源循环、压力测试或更深诊断。

## 6. 性能测试设计

### 6.1 已有微基准，只作为选型线索

历史小测试条件：同机、3 个真实分区副本、1,271,631 字节、767 条记录；两边执行校验、类型化解析和分区验证，优化构建，预热 10 次，每轮 30 批，7 轮取中位数。一批包含全部 3 个文件。

| 场景 | C# / .NET 8 | Rust | 比值 |
| --- | --- | --- | --- |
| 内存数据校验与解析 | 21.96 ms/批 | 7.19 ms/批 | 约 3.06 倍 |
| 系统文件缓存已热的读取+校验+解析 | 23.72 ms/批 | 7.01 ms/批 | 约 3.38 倍 |

两边记录计数及 ID/输入/绑定汇总校验一致。它不是对所有字段重新序列化后的字节级等价证明，也没有测整个 `ImageCacheState.Load` 的索引重建、重入、锁竞争或宿主绘图。

该原型、数据副本与依赖已经按临时测试要求清理，原始运行日志在会话记录中；不把这张表当作仓库里已有的可复现基准项目。本轮不重建或重跑同义解析微基准，后续只测实际接入后的收益，真实数据保存在私有位置。

微基准没有包含：跨语言调用、冷盘读取、全量索引加载、入库到就绪、Skia 绘图、编码、Emby 数据库、列表响应和生产峰值内存。C# 使用 .NET 8.0.32；此前读取的 Emby 自带运行时为 8.0.28。端到端对比必须固定实际宿主环境，不能把微小运行时差异或微基准结果直接外推。

### 6.2 最小端到端性能对比

| 场景 | 指标 | 对比要求 |
| --- | --- | --- |
| 启动与状态恢复 | 加载/校验/反向索引时间，进入可服务状态时间，工作集 | 包含真实 Rust → .NET 接入，不只 parse |
| 列表带图片标识 | 代表页耗时，查库/文件/网络次数 | 随主流程观察；小样本不报 p50/p95 |
| 入库预绘 | 输入就绪到成品提交时间、等待/绘图/编码/落盘分项 | 区分下载等待，固定队列负载与并发 |
| 批量补齐 | 图片/秒，CPU、峰值工作集、取消响应 | 同范围、同素材、同图像质量，不通过降画质换速度 |
| 缓存命中请求 | 响应延迟、实际绘图次数、文件变化 | 命中应为零绘图，不以 Rust 绘图更快代替命中正确 |
| 管理和评分 | 复用必要功能检查的耗时及请求数 | 不单独安排管理页面或评分性能测试 |

复用已有代表海报，在同机、相同参数下各执行 C# / Rust 一批受控制图，同时记录总耗时、实际绘图数和进程内存观察；启动/命中耗时从必要的加载和主流程中取得，不另建多套基准。首批只作粗略比较，不能据此宣称稳定倍数；仅当结果波动或是否回归仍不明确时追加最少轮次，结论仍不清楚则如实记录。没有具体疑点时不扩大样本、不测冷盘、不做持续压测，不在生产中清系统页缓存。内存仅在口径可比时报告，不能用独立 Rust 进程与完整 Emby 的 RSS 相减。

正确性优先，计时必须包含 ABI 成本。只记录样本能支持的结论，不为得到好看倍数重复测试；若有明确回归，再定位相关路径。

入口选择、网络等待不占绘图槽和跨语言数据路径的核验并入原有主流程/契约观察，不另加性能测试。PNG 压缩默认不调；只有同批分项计时确认编码是瓶颈，才用同一代表海报作必要参数对比，记录无损像素一致、耗时和文件大小，不能降低分辨率、进行颜色量化或改用有损格式。

## 7. 发布门禁

| 门禁 | 必须满足 |
| --- | --- |
| G0 宿主能力 | D1/D2/D5/D6 已闭环；没有未验证的“缺图禁止绘图”假设 |
| G1 数据兼容 | 旧配置/绑定/摘要可读，既有成品兼容边界明确，只有一个写入者 |
| G2 业务完整 | 05 保留项与本文精简矩阵无漏项；移除项无实现义务，旧字段保留、未支持设置明确提示 |
| G3 主动预绘 | 无用户请求也能完成入库制图；普通请求绘图次数为零 |
| G4 成品正确 | 成品路径/标识一致，失败不提前就绪，无原图污染与半成品 |
| G5 性能与资源 | 按相同输入端到端对比，结果和剩余瓶颈已记录 |
| G6 可回退 | DLL/原生库、配置、索引/队列与备份匹配，回退已在隔离环境验证 |

不满足门禁时保持未完成；不能用“先部署再观察用户是否投诉”替代功能或缓存一致性验收。

门禁只是引用前述最小验证的证据，不分别安排 G0—G6 测试轮次。隔离环境已证明的逻辑在生产不重测；生产只核查匹配包/ABI/状态加载和一个代表样本命中，必要的小范围正常入库观察可合并为试点记录。

## 8. 数据迁移与生产切换步骤

1. 固化当前运行包、配置摘要、插件 ID、素材和目标容器环境；检查是否存在活动预绘或其他真实写入者。
2. 备份匹配的旧 DLL、配置、`data/EmbyIcons`、`plugins/embyicons`；图片缓存保持原位，不盲目全库复制或删除。
3. 在私有状态副本上完成 Rust 导入和键对照；随后停止旧插件写入并完成最后保存，保留停写后的最终配置/状态备份，再执行正式导入，不能用早期副本覆盖期间新增状态。
4. 部署成套的 .NET 适配 DLL、Rust 原生库、必要原生图形依赖和版本/校验清单。继续使用 `plugins/embyicons.dll`，确保没有两份插件同时加载。
5. P9.2 首次受控切换即执行上述完整步骤：启动新后端，确认原生库/ABI、配置、索引和独立身份，只放开试点范围的后台预绘；其他范围复用已有有效成品或返回原图，不运行第二份旧插件。
6. 引用隔离环境的主流程/恢复结果；本次部署重启同时确认加载与一个代表样本命中，不额外重启或重跑全部场景。
7. P9.3 仅逐步扩大自动制图与补齐范围；无新变更不再次部署或重启，并发仍受配置约束。

普通升级不修改 `PersistedVersion`，不清空 `cache/images`。新后端不得在未验证就绪时批量宣布已有画面失效。

## 9. 回退步骤

- 原生库无法加载、标识异常漂移、请求触发绘图、配置损坏或严重端到端回归时，停止新后端及作业，先保留问题证据。
- 恢复匹配的旧 .NET 插件与原生依赖集合、配置、旧索引/摘要快照，移开不兼容的新队列/状态文件；不要仅替换 DLL 却留下不兼容状态。
- 保留原有正确成品。只处理有证据确定由本轮产生的无效/半成品，不按目录全删。
- 重启并核查旧插件身份、配置、样本图片、文件与关闭后台任务的情况。
- 说明旧后端是否仍存在惰性绘图行为；回退成功不等于 Rust 的严格预绘目标已完成。
